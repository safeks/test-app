# Решение

## Сколько заняло

Работа была начата примерно в 15:30 по местному времени, выполнение самого задания заняло около часа с учётом ознакомления ТЗ, создания репозитория и других организационных вещей.

## Что сделано и что не успел

Сделано всё из частей 1–3 и одно дополнительное задание — тесты на логику фильтра (`npm test`).

- Загрузка матчей, состояния: загрузка, ошибка с «Повторить», пустой список (свой текст для каждого фильтра). Если данные уже есть, а обновление упало — список остаётся, сверху плашка с ошибкой.
- Карточка: команды, счёт, дата и время в часовом поясе устройства, статус по-русски (у идущего — с минутой).
- Фильтр Все / Предстоящие / Завершённые со счётчиками.
- Кнопка «Обновить» и pull-to-refresh, подпись «Обновлено N сек назад».
- Исправлены оба бага, звёздочка подключена к карточкам.

Структура: `types/match.ts` — типы данных, `api/matches.ts` — запрос, `hooks/useMatches.ts` — состояние экрана, `utils/match.ts` — чистые функции фильтрации и форматирования, компоненты `MatchCard` и `FilterTabs`.

## Решения

**Статусы в фильтре.** «Завершённые» — только `finished`, то есть матчи с окончательным результатом. «Предстоящие» — всё, что ещё будет сыграно или идёт сейчас:
- `live` — результата ещё нет, и идущий матч пользователю как раз важнее всего увидеть;
- `postponed` — матч ещё состоится, просто без даты; если его спрятать, будет выглядеть так, будто он пропал.

Неизвестный статус (если сервер пришлёт новый) не относится ни к одной группе: такой матч виден во «Все» с подписью «Статус неизвестен» — не теряется и не попадает в группу наугад.

Фильтр работает по статусу, а не по сравнению даты с текущим временем: у `m4` статус `live`, а дата — неделю назад, сравнение дат отнесло бы его к прошедшим.

**Неочевидные случаи в данных:**
- Счёт `0:0` (`m2`) — проверяю `score === null`, а не «истинность», иначе ноль теряется.
- `score: null` у несыгранных матчей — показываю `– : –`.
- `startsAt: null` у перенесённого `m7` — «Дата не назначена» (`new Date(null)` дал бы 1970 год). Некорректную строку даты обрабатываю так же.
- `minute` есть только у `live` — показываю «Идёт · 67'».
- Время в UTC — форматирую через `toLocaleString('ru-RU')` без `timeZone`, получается пояс устройства.

**Прочее:**
- `fetch` не бросает ошибку на 404/500 — проверяю `response.ok` вручную.
- Ответ устаревшего запроса не перезаписывает свежий (счётчик запросов в `useMatches`) — на случай быстрых повторных нажатий.
- В браузере нет pull-to-refresh, поэтому есть и кнопка «Обновить».
- В `config.ts` вместо заглушки `OWNER/REPO` — адрес этого репозитория.

**Библиотеки:** `jest` и `jest-expo` (только для разработки) — официальный способ тестирования в Expo, нужен для дополнительного задания.

## Баги из части 2

1. Звёздочки: проверка «матч в избранном?» делалась через `indexOf(id)`, то есть искала, на каком месте в списке избранного стоит матч, и возвращала −1, если его там нет. Дальше это число превращалось в `Boolean`, а он превращает любое число, кроме 0, в `true`. Поэтому при −1 (матча нет) получалось `true` и звезда горела, а при 0 (матч стоит первым) — `false` и звезда гасла. По сути проверка спрашивала не «есть ли матч в списке?», а «матч не на первом месте?».
   Вторая проблема — в `toggle`: матч добавлялся через `push` прямо в тот же массив, который лежит в состоянии, и этот же массив передавался в `setFavorites`. React сравнивает старое и новое значение по ссылке, видит тот же массив и решает, что ничего не изменилось, — экран не перерисовывается. Изменение всплывало позже, при любой другой перерисовке (например, при смене фильтра), отсюда «то ничего не меняется, то звезда гаснет».
   Исправление: проверка через `includes`, который возвращает именно `true`/`false`, а при нажатии создаётся новый массив, и React видит изменение.
2. «Обновлено N сек назад»: таймер создавался только при первой отрисовке компонента (`useEffect` с пустым массивом зависимостей), а в тот момент `seconds` = 0. Таймер «запомнил» этот ноль и каждую секунду делал одно и то же: ставил 0 + 1. В итоге получалось 1, 1, 1…
   Не сбрасывался счётчик потому, что компоненту передают время последней загрузки (`since`), но он его вообще не читал — просто считал секунды с момента своего появления, поэтому обновление на него никак не влияло.
   Исправление: секунды больше не считаются, а вычисляются — текущее время минус время загрузки. Ещё добавили остановку таймера (`clearInterval`), раньше он не останавливался.

## Как я использовал ИИ

Claude Code (агент в терминале). Работал по шагам: агент предлагал решение и объяснял его, я проверял результат в браузере и только после этого коммитил.

Где ИИ ошибался или ответ был неполным:
- **Зависимости для тестов попали не туда.** `npx expo install jest ... --dev` на Windows поставил пакеты в `dependencies` вместо `devDependencies` — флаг не дошёл до npm. Заметили по `git diff package.json`, перенесли вручную.
- **Проверка часового пояса ничего не проверяла.** Чтобы убедиться, что время показывается в поясе устройства, агент запустил форматирование с разными `TZ=...` — вывод совпал, потому что Node на Windows игнорирует `TZ`. Заметили, что результат подозрительно одинаковый, и перепроверили через явный `timeZone`.
- **Данные не загружались (404).** Сначала предположение было «GitHub ещё не обновил raw-файлы», но оказалось, что мой репозиторий был пустым — его нужно было создать через «Use this template». Выяснили через GitHub API и `git ls-remote`.

Как проверял: `tsc --noEmit` после каждого шага, ручная проверка в браузере (состояния, фильтр, звёздочки, счётчик), тесты. Чтобы убедиться, что тест не проходит «всегда», временно вносил в код баг с 0:0 — тест упал.
